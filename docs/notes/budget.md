# Budget tab (how it works)

- **Budget is about ranges; Add is about today.** Per category it shows how much was spent against how much allowance was given in the range. **No carry-over:** a range simply adds up every allowance and every expense inside it.
- **It reads the summary docs, not `transactions`, and adds them up on the phone (1.7.0).** `BudgetRepository.getBudgetSummary` listens to `daily_history` (userId + date range) for day filters, and to `monthly_history` for Last 3/6 Months and This Year (`BudgetChartFilter.isWholeMonths`, 3–12 reads instead of 88–331). `summaryFromDays` / `summaryFromMonths` (`BudgetTotalSummaryModel.kt`) add up the category maps into `totals`, `counts`, `allowances`, plus over/unplanned day counts, `badDays`, `expenseByWallet` and `hasDayCounts`. Insights reads the same docs for the same filter, so both screens always match. A range costs at most 1 read per day instead of 1 per transaction (one filter switch went from ~234 reads to ~30). The maps are written by the Add tab's batches (`add-transactions.md`).
- **`date` on a daily doc is the time of that day's latest add**, so it always falls inside its own day and the range query works. Edit and delete never change it. The query needs a composite index (userId + date); a missing one shows up as a Logcat link that creates it.
- **Old days were backfilled.** Days saved before the category maps existed used to add ₱0. On 2026-11-21 a one-time script rebuilt the maps on every daily doc from its transactions (see `budget-insights.md`), so every day counts now.
- **Range ends at the end of the last day** (`BudgetRepository`: `lastDay.plusDays(1).atStartOfDay().minusNanos(1)`), not a frozen "now", so new transactions show live.
- **Filters** are the `BudgetChartFilter` enum (`domain/models/budget/`, `@StringRes` labels). One `OnChangeFilter` event; `OnGetBudgetSummary` is a no-op if the listener is already live. **Custom range** opens a Material 3 `DateRangePicker` (future days disabled, start only = one day). The VM keeps the picker's UTC-midnight millis, and `BudgetRepository.utcMillisToLocalDate` reads them back in UTC to get the same calendar day, then local start/end of day. The chip shows "Nov 3 – Nov 9".
- **Budget is a bottom-nav tab: no ON_STOP stop and no pull-to-refresh.** The listener stays live while the app runs. A day rollover while open doesn't matter much, because every change re-emits anyway.
- **Pie tap gotcha:** compose-charts 0.1.10's `PieChart` registers taps with `pointerInput(Unit)`, so it keeps the **first** `onPieClick` forever. `ChartSection` therefore holds the selection in a **non-keyed** `remember { selectedLabel }`; keying it (e.g. `remember(budgetData)`) replaces the state the old lambda writes to, and taps stop working after a filter change or live update. Pie % uses the real total.
- **UI (1.7.0, see below):** Money out, Money in, the pie, How it went, Where it went wrong, then one breakdown card, biggest spending first. Each `BudgetItem` row has one wrapping line, "32 transactions · ₱520.00 under its ₱6,700.00 allowance" (green), "… over its …" (red) or "No allowance set · unplanned" (amber), with a bar toward the allowance (none without one). Categories with nothing collapse into one line. A thin top loading bar replaces the LoadingDialog.
- **Quirks:** a category not in the dropdown list gets no row or slice but still counts in the totals. Rows with ₱0 spent and ₱0 allowance aren't tappable. Tapping a row opens per-category Insights (`budget-insights.md`).

## Bills & subscriptions card (1.6.0)
- **Under Breakdown, never part of "Spent"** (labelled "Not in your allowance"): what the auto-charge posted to cards in the Budget range. Mockup: https://claude.ai/artifact/KU8rGEjPfDPsY7m8f8cDYF (option A).
- **Data = the posted charges, not the schedules:** since 1.7.0 they come out of `WalletService.getMoneyMovements(start, end)` (see "Money in / out" below), filtered to subscription/installment. **Needs the composite index** `wallet_movements (presetKey, userId, date)` (created 2026-11-25). A deleted charge, a deleted schedule and a closed card all still add up right.
- `BudgetRepository.getBudgetMoney` (injects `@FirebaseWallet WalletService`) `combine`s it with `getWallets()` + `getRecurringCharges()` (the same queries Home and the Wallet tab run, so the SDK shares them) → `buildBudgetBills` (`domain/models/budget/BudgetBillsModel.kt`) groups by `recurringId`.
- **Rows** (`ui/budget/components/BudgetBillsCard.kt`): subscription "Visa · every month · next Nov 30", installment "BPI card · 6 of 24 · next Dec 25" (the posted note + the next date) with a bar, "· paid off" when done, "· 2×" when charged more than once. A deleted schedule shows just the card. A closed card shows "Closed card", faded and not tappable. Tapping a row pushes `WalletRecurringNavigation(walletId)` (same pattern as Home pushing wallet details); Back returns to Budget.
- **Next up** = the soonest next charge of the active schedules, only when the range reaches today. **Empty** range: "No bills this month" / "No bills in this period". **Hidden** with no credit card and nothing charged.
- **Listener:** `billsJob` (dashboard instance only), started with the summary on ON_START, restarted on a filter change, no ON_STOP (tab rule). **Fails quietly:** an error hides the card with no dialog, so a missing index or rules problem never blocks the summary.
- **Cost:** 1 read per charge in the range (a few a month), plus the shared listeners.
- **Known/accepted:** after a filter change the previous range's bills show until the new range emits; a due charge not yet auto-charged can show a past "Next up" date (rare, the charge runs on every open).
- **"stopped" (1.6.1):** a subscription whose schedule was deleted (paused, e.g. Netflix deleted and added again) has no schedule doc left, so its row says "stopped" next to the card name, instead of looking like a duplicate of the new one.

## Where the money went (1.7.0)
- **Goal:** answer "how much did I really spend in <filter>, and where did I go wrong?" first, then the breakdowns. Design: https://claude.ai/artifact/1UCujcwsg1mo6DgE1qGwSQ. Light mode only; dark mode is planned for 1.8.0.
- **Order** (`BudgetScreen`, one file per card in `ui/budget/components/`):
  1. `MoneyOutCard`: "Money out" + the filter chip on top, the total with the ⓘ "Wallets vs allowance" next to it, and the date range under it. One divider under the total, then everyday spending (+ `AllowanceLine`), card bills and other money out as the parts of the total (1.7.1: the divider used to sit under Everyday, which made Everyday read as the total).
  2. `MoneyInCard`: dark like Home's balance card; the biggest entry, then "₱X more went out than came in". Only shown once wallets exist.
  3. `ChartSection`: a full pie (`Pie.Style.Fill`) with a name + % legend. The tapped slice (or the total) shows in a line under it, never inside the pie.
  4. `HowItWentCard`: up to 4 rule-based sentences (spent vs allowance, biggest category and whether it had an allowance, the category with the most bad days or "all N days stayed within", card bills). No AI, 0 extra reads.
  5. `WhereItWentWrongCard`: only categories that went over or were unplanned. Red chips are over, amber chips are unplanned; no allowance gives "₱X unplanned", over overall gives "₱X over · N days", under overall but with bad days gives "Over on N days" / "N days unplanned". Tapping a row opens Insights.
  6. Breakdown, then Bills & subscriptions.
  7. `BudgetWalletsCard`: expenses (`expenseByWallet`) + bills/other money out per wallet. Tapping a row opens `WalletDetailsNavigation`. "Don't deduct" expenses aren't listed.
- **Unplanned** = spending on a day with no allowance for that category (`DayMark.of`: spent 0 is ok, no allowance is unplanned, spent > allowance is over). It counts as a bad day with "over" but is labelled and coloured apart (`R.color.unplanned*`). "Left" became "under" everywhere in Budget (allowance isn't money; Home keeps "accumulated allowance").
- **Money in / out:** `WalletService.getMoneyMovements` = `wallet_movements` with userId, `presetKey in WalletMovementModel.MONEY_PRESETS`, date range. It uses the **same index** as the old bills query, so no new index. Left out: transfer, card_payment, correction and withdrawn (bank → cash is a transfer, a user decision); a retyped transfer (presetKey "") is dropped by `transferId`. `buildBudgetMoney` gives the bills, money in (+ biggest), other money out and out per wallet. A hand-typed "Take out" counts as money out. Keep `MONEY_PRESETS` in sync with `WalletMovementPresets`.
- **Ranges:** Last 3/6 Months = this month and the ones before, as whole months (`rangeFor`). Custom = the exact days everywhere. Tapping a category passes the dashboard filter in the Insights route (`BudgetInsightsScreenNavigation(category, filter, customStart, customEnd)`), applied only on Insights' first load.
- **Day counts need marks:** `hasDayCounts` is true only when every month with spending has `dayStatusByCategory`. Otherwise the bad-days sentence and day chips are skipped, so an older, unmarked month never reads as "no bad days".
