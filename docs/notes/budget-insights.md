# Budget Insights (how it works)

- **Per category, opened from a Budget dashboard row.** `BudgetInsightsScreen` uses its own `BudgetViewModel` instance (one VM per module), so its `filter`/custom range are its own, default This month. `insightsCategory` empty = the dashboard instance; `restartForFilter()` uses it to restart the right listener.
- **Mockup / design source:** https://claude.ai/artifact/93MPhUCgKNnCznyttSvZ55. Each section has its own `ui/budget/components/Insights*.kt` file (shared helpers like `peso`, `InsightsCard`, `DeltaChip` in `InsightsCommon.kt`); math lives in `domain/models/budget/BudgetInsightsModel.kt` (`buildBudgetInsights` from daily docs, `buildBudgetInsightsFromMonths` from monthly docs).
- **Two read paths, picked once per load in `BudgetRepository.getBudgetInsights`.** ≤ 31 days: `daily_history` docs. Longer, and **This year always** (one bar in January, user decision): `monthly_history` docs, with the range snapped to the 1st of its first month. Custom goes by its length. The builder that read the docs sets `isLongRange` (a field, not `dayCount > 31`): a range clipped to a recent setup day can be ≤ 31 days and still be monthly, and deriving it from the length drew an empty day chart (caught in review, 1.6.1).
- **Never before tracking started (1.6.1).** `WalletService.getTrackingStart()` = the physical wallet's `createdAt` (one `get()`, null on failure). `trackedFrom` clips the range start and the "before" period to it, so months before the account existed don't count as ₱0 (they made Last 6 months include an empty May and "Compared to before" show ▲102%). Quiet days **after** setup still count as ₱0, on purpose (user decision: not spending is real). A loaded doc older than the setup day wins (accounts from before wallets; accepted as is). Unknown setup day, or one after the range = no clipping. The compare card reads `previousStartDate`, adds the year when it differs, and says "Nothing tracked before this range yet" with 0 tracked days; ₱0 before still shows "—". Either way it's **one listener** covering the previous same-length period plus the range; `BudgetRepository.getBudgetInsights` splits them with `partition` for "Compared to before". Cost: ≤ ~62 reads for a month, ~12 for 6 months (vs ~184 daily docs).
- **`monthly_history/{uid}_{yyyyMM}`** (`MonthlyHistoryModel`): `userId`, `month` (Timestamp, 1st 00:00 local), `expenseByCategory`, `allowanceByCategory`, `countByCategory`, `weekdayExpenseByCategory` ({cat: {"MON".."SUN": cents}}). Written in the same batch as the daily doc (`FirebaseTransactionServiceImpl`), nested maps + `increment`, empty maps skipped. Query needs a composite index (userId + month). Rules: owner read/delete; create/update only on `{uid}_[0-9]{6}` with `userId == uid`.
- **`inMonthly` guard + one-time backfill.** Adds set `inMonthly: true` on the daily doc. Edit/delete touch the monthly doc only when the day has it, so a day without it never decrements into negatives. On 2026-11-21 a one-off script (outside the app, not in the repo) rebuilt the category maps of every existing daily doc from its `transactions` subcollection, set `inMonthly`, and rebuilt every `monthly_history` doc. So all days now count on short and long ranges, and the guard only matters for docs written by older app versions.
- **Drill-in** (long ranges): tapping a month bar/row sends `OnOpenInsightsMonth(month)` → `insightsMonthJob` reads that month's daily docs (`getBudgetInsightsMonthDays`). `null` goes back. A range change closes it; ON_START restores it.
- **Day sheet:** tapping a day bar → `insightDayJob` listens to that day's `transactions` subcollection and filters by category on the device. Stopped on dismiss, in `DisposableEffect` (rotation) and on ON_STOP; ON_START resumes it if the sheet is still open (`resumeInsightDayListener`, the VM keeps the last `insightDayDocId`). Stopping also clears `isInsightDaySheetLoading`, so a cancel before the first result can't leave the spinner on.
- **Listeners:** `insightsJob`, `insightsMonthJob`, `insightDayJob`. Insights is a pushed screen, so ON_STOP stops them (the dashboard tab never stops). `OnGetBudgetInsights` is a no-op if already live for the same category.
- **Overspent rules:** a day is over when spent > 0 and spent > allowance (no allowance + spending = over, same as Add). With **no allowance in the range** nothing is counted ("—"). Long ranges count **overspent months** only, because monthly docs can't tell days apart; weekday "over" lines show only on short ranges.
- **Chart is a Canvas, not compose-charts:** `ColumnChart` can't color bars per value under a dashed allowance line, nor give a tap per bar. Helpers: `niceStep`, `axisLabel`, `ChartLegend`. Days draw allowance as one step line, months as a short dash per bar.
- **Insight sentences** (`insightLines`): top weekday (≥ 7 days, ≥ 5% more), overspending, biggest day / heaviest month (compared with the *other* months' average, 1.6.1), share of all spending. Each is **one string resource**: Android trims leading spaces in strings.xml, so splitting a sentence into "bold" + " rest" lost the space.
- **Say "Food allowance", not "allowance".** Users read a bare "allowance" as the overall total. `AllowanceLine(category = …)` prints the category on Insights; the dashboard total line passes none.
- **Month by month** shows ₱/day (bold) + ▲▼ vs the month before, because partial months make totals misleading.
